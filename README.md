# Пено — свой кусочек деревни

Небольшой статический сайт-прототип агрошеринга.

## Быстрый запуск

Просто откройте `index.html` в браузере.

Для GitHub Pages:
1. Создайте репозиторий на GitHub.
2. Загрузите все файлы и папку `images`.
3. Settings → Pages → Deploy from a branch.
4. Выберите `main` и `/root`.
5. Через некоторое время GitHub выдаст адрес сайта.

## Как добавить свои картинки

Положите фотографии в папку `images`.

Главные:
- `images/hero.jpg` — фотография участка/сада для первого экрана.
- `images/house.jpg` — фотография старого дома.

Карточки:
- `raspberry.jpg`
- `currant.jpg`
- `apple.jpg`
- `greens.jpg`
- `potato.jpg`
- `strawberry.jpg`

Если хотите другие имена, откройте `script.js` и поменяйте значение `image`.

Рекомендуемый размер фотографий: 1600×1000 или больше. JPG/WebP подходят лучше всего. Сейчас в архиве стоят простые SVG-заглушки, чтобы сайт работал сразу.

## ВАЖНО: реальная оплата

GitHub Pages — это статический хостинг. Данные банковских карт нельзя принимать и хранить в `index.html`.

Для настоящей оплаты нужен платёжный провайдер и небольшой серверный endpoint:
- пользователь нажимает «Перейти к оплате»;
- ваш сервер создаёт платёж;
- сайт перенаправляет пользователя на страницу оплаты провайдера;
- сервер получает уведомление об успешном платеже;
- заказ сохраняется в базе.

В `script.js` сейчас стоят две демонстрационные функции:
`/api/create-payment` и `/api/create-donation`.

Их можно подключить к ЮKassa, T-Банку, CloudPayments или другому подходящему провайдеру после регистрации проекта и настройки юридической части.

## Что заменить перед публикацией

1. Цены и описания в `script.js`.
2. Фотографии в `images`.
3. Email `hello@example.ru`.
4. Юридические реквизиты в footer.
5. Условия участия, правила получения урожая/дохода.
6. Реальный платёжный backend.
7. Политику конфиденциальности и согласия, необходимые для вашего способа работы с персональными данными.

## Важное юридическое замечание

Не обещайте гарантированную прибыль от урожая. Перед запуском определите юридическую модель проекта, договор с пользователем, правила распределения урожая/выручки, возвраты, налоги и условия пожертвований.
